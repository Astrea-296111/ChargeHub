# Codex 分阶段实施任务

## 首轮可直接使用的提示词

请把本资料包作为 ChargeHub 后端项目的实施规范。先读 README、01-project-plan.md、03-schema.sql、04-openapi.yaml 和 06-acceptance.md，检查相互冲突并记录到 docs/decisions，不虚构测试结果。第一轮只完成 T00 和 T01，不提前实现整个交易系统。

使用 Java 21、Spring Boot 4.1 系列、MyBatis Starter 4.0 系列、Maven Wrapper、MySQL 8.4 和 Docker Compose，具体补丁版本及镜像 digest 在 T00 核实并锁定。建立模块化单体，设备模拟器和支付模拟器保留独立进程。为未来实现创建明确的接口，但未实现的业务接口不能统一返回成功或生成假账单。

T00 T01 完成后，交付仓库目录、依赖锁定记录、空库迁移、演示身份和角色骨架、健康检查、CI、真实 MySQL 的集成测试，以及准确的启动和测试命令。每次报告区分已执行、未执行及受环境限制的验证，列出下一阶段的具体入口。不得生成虚构的企业名称、任职历史、用户规模或性能提升数字。

## 工作约定

每个任务建立一个独立变更集和验收记录。新业务规则以 B 编号关联测试，新接口必须修改 OpenAPI，新增数据库字段必须提供 Flyway 升级脚本。代码注释解释边界与取舍，不写与实现不符的高并发或高可用宣传。涉及状态变化的接口至少验证正常路径、重复调用和关键失败路径。

每轮输出包含变更目的、运行方式、实际测试结果、已知限制、迁移影响与下轮任务。工程中的 `./mvnw verify`、`make demo`、`make test-invariants` 和 `make load-test` 是待实现的目标命令，只有相应脚本存在并已验证后才能宣称可用。

## T00 技术与参考基线

输入：项目书第 2 和 6 节、参考资料。

实施：建立 `docs/decisions/ADR-001-architecture.md`；锁定 JDK、Spring Boot BOM、MyBatis、Flyway、Testcontainers、容器镜像与 Maven Wrapper；确认 Flyway MySQL 驱动支持所选版本。记录实际阅读的芋道、mall、SteVe 分支和 commit SHA，不把参考仓库当前 master 当成本项目依赖。核对计划使用的许可证、保留来源文件。

完成：JDK 21 可构建最小应用，MySQL 可连接，环境版本记录可复现。若构建环境不能联网，明确记录缺少的依赖，不跳过构建却报告成功。

## T01 仓库和基础设施

实施：建立项目书规定的 Maven 模块；为 API、Worker、MySQL、Redis 与两个模拟器预留 Compose 服务；将 03-schema.sql 转为首个 Flyway 迁移；配置 UTC、UTF-8、结构化日志、异常协议、健康检查与 CI。实现 BCrypt 登录和 CUSTOMER、OPS、FINANCE、ADMIN 的服务端授权，测试账号从环境或 dev 初始化逻辑生成。

完成：空数据库启动成功，重复启动不重建数据，Flyway 校验通过，真实 MySQL 容器测试通过，普通用户不能访问管理接口。初版模拟器可仅有健康检查，业务能力明确未完成。

## T02 站点 费率与报价

实施：支持站点、枪、费率草稿与发布。校验时段无空档、无重叠且覆盖 24 小时；发布后只允许新增版本。实现纯函数计费计算器与估算报价，使用 Clock 和 ZoneId 注入。报价不占用枪或权益。

完成：07-billing-vectors.json 所有样例可作为 Java 参数化测试复算；跨日时段、负电量、舍入与费率变化测试通过。数据库历史费率不能被管理端接口覆盖。

## T03 会员与优惠券

实施：dev 种子开通演示会员；建立月度额度、权益预占和流水。实现模板发布、每人限领一张、我的券、预占、核销和释放。先用 MySQL 条件更新，不先上 Redis 库存预扣。总库存、额度上限和释放过期券逻辑对应 B08 至 B12。

完成：1000 用户竞争 100 张券恰好成功 100；同用户并发领券只成功一次；会员 2 次额度的预占与释放可核对；第三次无额度时给出明确业务错误。测试覆盖取消后券自然过期。

## T04 订单与请求幂等

实施：实现创建订单事务、绑定用户和连接器、规则快照、Idempotency Key 与请求摘要。固定目标用户到订单再到资源的锁顺序；所有失败原子回滚。实现订单查询与数据归属校验。

完成：两用户抢同一枪只一单成功；同用户抢不同枪只一单占用；建单事务在锁券后失败不会泄露绑定或权益；同 Key 同请求返回原单，不同请求 409。未付款不能下发启动事件。

## T05 预付款与设备启动

实施：独立支付模拟器实现创建、成功、查询、关闭、通知签名和故意丢通知。平台实现支付事实处理入口与支付回调；建立 Worker 和 Outbox；设备模拟器支持 START 和 QUERY_SESSION 及重复 commandId。

完成：20 次成功回调只生成一笔 CAPTURE 和一个有效启动；支付成功与取消同时发生不丢钱；启动超时但设备实际成功时恢复 CHARGING；已取消订单晚到支付不重新开充。网络调用不持有业务数据库事务。

## T06 计量与停止

实施：设备模拟器实现连续序号、边界电表和 final_seq，支持 STOP、断线恢复、重复和乱序。平台收件先持久化再确认，维护原始事件、有效计量和异常原因。按预付款优惠前费用设置止损并保留查询恢复。

完成：重复计量不重复收费；缺边界采样时不出账；补传后恢复；计量下降或同序号冲突进入 REVIEW；停止回执丢失后通过查询恢复；同一设备不能被两个订单同时控制。

## T07 正式账单与退款

实施：完成不可变账单及明细，会员和券的最终确认、释放，创建差额或取消全额退款。模拟器实现按 refund_no 幂等退款及查询；平台维护在途退款额度和成功额度，不将 UNKNOWN 当失败释放额度。

完成：20 kWh 样例正式应付 2100 分、退款 7900 分；重复结束事件只出一张账单；退款成功但通知丢失时查询补录；任意重复回调不超退；无电量取消恢复权益并全退。异常超预付产生 SHORTFALL 而非伪造闭合。

## T08 对账与运营修复

实施：模拟渠道独立导出支付和退款账单；建立批次、哈希、差异项、查询确认与补录。实现财务重试和操作审计。禁止通过直接 UPDATE 把账单改成匹配。

完成：正确识别渠道有平台无、平台有渠道无、金额不符与退款未同步；同账单重复导入不重复修复；所有补单仍走统一事实处理服务；对账后运行资金和权益核对 SQL。

## T09 消息队列与故障恢复

实施：P1 接入一个确定版本的 RocketMQ 5 客户端与 Broker 组合，先做独立消息烟测再接业务。保留 Outbox，明确本地提交、发送和标记之间的崩溃窗口。实现 consumer_inbox、死信可见性、原事件重放与租约接管。

完成：发布成功后杀进程可重投；业务提交后 Ack 前杀消费者不会重复退款；两个 Worker 不永久争用一条任务；服务恢复后积压按限流清理。对确定性无效消息归档，不无限重试。

## T10 展示 部署与压测

实施：做简洁页面或 API 演示台，覆盖站点、领券、充电状态、账单退款与差异列表；界面显示设备与支付为模拟。提供 Compose 启动、环境变量模板、数据库备份恢复、发布和应用回滚。搭建最小监控仪表，执行验收环境中的压力测试。

完成：新环境仅按 README 即可复现演示；无密钥进入 Git；本地和生产 profile 隔离；50 RPS、1000 领券竞争与 100 会话上报的实际结果完整记录。性能不达标时定位和修改后重复同一测量，不编写目标数字冒充结果。
